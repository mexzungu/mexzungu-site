Known Limitations

Gaps

Open gaps in coverage, tooling, or process. Each has an owner and a resolution path.

GapImpactOwnerResolution path
No automatic staleness detection Stale memories persist until Nina manually audits them Bowie Build a staleness scorer that flags entries older than 30 days where the referenced file has not changed. Run as part of weekly synthesis.
MEMORY.md index has no priority or relevance weighting All entries loaded with equal weight at session start; high-value entries do not surface first Nina Add a relevance tier (core / active / archive) to MEMORY.md entries. Loader surfaces core entries first when approaching context limits.
Cross-session feedback loop is manual Patterns detected by Bruce in weekly synthesis require manual propagation to standing-rules.md Bruce Build an automated rule-promotion loop: Bruce flags a pattern, Nina drafts a rule, Pepe approves, Janis writes to standing-rules.md. Currently all manual.
No versioning on individual memory files When a memory is updated, prior state is lost unless git history is queried manually Bowie Git history provides implicit versioning. Add a convention: append a dated changelog block to each memory file on update so prior state is visible without a git blame.

Non-Negotiable

Standing Rules

Applies to every knowledge capture, every session, every cluster.

  • One canonical location per fact. Never duplicate knowledge across files. Cross-reference with links. Duplication creates drift and contradiction.
  • MEMORY.md must stay under 200 lines at all times. Lines past 200 are truncated and invisible. Every write triggers a line count check.
  • Before acting on any stored memory, verify it is still current. A memory that names a file path, function, or flag is a claim it existed when the memory was written. Check before recommending.
  • Sensitive client patterns require Lemmy gate before storage. Anything touching legal exposure, financial deal terms, NCA succession, or personal health data is held until Lemmy clears it.
  • Cluster log isolation enforced. Panda entries go in panda.md. Duara entries go in duara.md. Never blend clusters in a single note.
  • State vs knowledge: evolving counters, timestamps, and session-specific tracking go to STATE.md files, not MEMORY.md. MEMORY.md is for durable knowledge only.
  • Every feedback memory must include a WHY line and a How to apply line. A rule without context cannot be applied correctly in edge cases.
  • New knowledge gets written before the session ends. Not after. Not in the next session. Before. Rolling autosave at every task breakpoint is the mechanism.
  • Yoda Janitor runs every Monday 03:00 CET and prunes noise from standing-rules.md and guide files. Do not disable it and do not add trivial entries that will just be pruned.
  • Every memory write is committed to git immediately. No session ends with unstaged knowledge files. Uncommitted memory is lost memory.
