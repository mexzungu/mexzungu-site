The 4 Engines

Engine Map

Engine 1 of 4
SM Content Engine
Freddie Mercury (CMO)
Turns expertise into consistent, high-quality public content across LinkedIn, X, Instagram, and Outlaw Chronicles. Owns the brief-to-publish lifecycle. Feeds deal-level signals to CAE via Annie.
Trigger
Calendar cron Mon 06:30 CET + Freddie brief
Output
Published posts + OC issues + deal signals to CAE
Engine 2 of 4
SM Engagement Engine
Joni (quality) + Grace (posting)
Converts audience engagement into relationships. Every substantive comment gets a reply. Every DM that signals genuine interest gets a response. Deal-level signals go to CAE immediately.
Trigger
Post-publish event + daily scan 07:30 CET
Output
Replies posted, DMs sent, deal signals to CAE
Engine 3 of 4
Connection Acquisition Engine
Jagger (CGO) + Joan (execution)
Turns relationships into signed engagements. Runs every morning at 07:00 CET. Owns everything from signal detection to the Go decision. Calls the Proposal Engine and receives the countersigned EL event.
Trigger
Daily cron 07:00 CET + inbound signals on any channel
Output
Go decision to Proposal Engine. EL countersigned: Delivery ExCo notified.
Engine 4 of 4
Proposal Engine
Prince (quality gate) + Lemmy (CLO)
Owns the full proposal lifecycle once the Go decision lands. Builds the proposal page, auto-generates the engagement letter from client selections, manages DocuSeal inline signing, and fires the countersign event back to CAE.
Trigger
Go decision from CAE Phase 5.3 (proposal-brief.md path)
Output
Countersigned EL event back to CAE Phase 5.4
Signal Routing

How Engines Pass Signals

Every inter-engine signal has a defined sender, payload, and receiver. Nothing passes informally.

From Signal To How
Annie (SM Content) Deal-level engagement detected in comments or analytics CAE Phase 0 queue write_brain + update_lead. State=new, source=sm-content
Joni (SM Engagement) DM or connection signal classified as Class C CAE Phase 0 queue write_brain + update_lead. State=warm, source=sm-engagement. Immediate, no batch.
Grace (SM Content) Post published notification SM Engagement Engine Phase 0 write_brain. Triggers engagement scan immediately.
CAE Phase 5.3 (Joan) Go decision with proposal-brief.md path Proposal Engine (Prince) Telegram to Prince. CAE enters waiting state.
Proposal Engine (Prince) Countersigned EL event CAE Phase 5.4 (Janis) Telegram or write_brain event. CAE resumes: CRM=won, Delivery ExCo notified.
Lars (CAE Phase 5.5) Delivery handoff ping Founders Delivery Engine Telegram OPS message. Client name, scope, practice lead, kickoff date.
Showtime Gates

Every Point That Requires "Very Well"

All Showtime gates across this macro engine. Nothing in this list fires without Pepe's explicit approval.

Showtime Gate Index: Macro Engine I
  • SM Content, Phase 3: Liability claim detected in content. Anselmo flags. Pepe must approve before Grace deploys. Fire Away is the trigger.
  • SM Engagement, Phase 1.6: Hostile or negative reply received. Joni drafts 3 options. Pepe chooses which to post (or not). Never auto-post.
  • SM Engagement, Phase 3: Connection outreach to any contact Pepe has not previously engaged. First contact = Showtime. Fire Away required.
  • CAE, Phase 0.9: Conflict detected on new lead candidate. Lemmy flags. Pepe must explicitly clear before any contact is made.
  • CAE, Phase 1.7: First contact message drafted for any new lead. Queued to Telegram thread 7. Fire Away is the only trigger.
  • CAE, Phase 4.6: Discovery call scheduling with a contact Pepe has not previously met. Invite not sent until Fire Away received.
  • CAE, Phase 5.1: Non-standard fee structure required. Gene flags. Pepe sets pricing before proposal brief is written.
  • CAE, Phase 6.1: Graceful close message to any contact at No-Go stage. Joan drafts. Fire Away before Grace sends.
  • CAE, Phase 6.3: D30 referral ask on won contacts. Once per engagement only. Fire Away required.
  • Proposal Engine, Phase 3: EL send to client. Proposal built and reviewed. Pepe approves EL before it goes out. Fire Away required.
