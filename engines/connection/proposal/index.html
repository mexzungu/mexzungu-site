Proposal Engine

The Core Promise
Non-negotiable
The client never leaves the proposal page to sign. The engagement letter is embedded directly via a DocuSeal inline widget, so signing happens in the same view where the proposal is read, with no email attachments, no external redirect, and no portal login required.
The Flow

Five phases, one deal closed

Go brief in, countersigned EL out. Every phase is either automated or gated by Fire Away.

1
Intake
Go brief received from CAE Phase 5.3. Gene checks fee against approved rate card. Lemmy runs conflict check across active clients. Bruce reviews the framing. Non-standard fee or any conflict escalates to Pepe before build starts.
2
Build
Slug generated as client-name-kebab-YYYY-MM. Proposal page deployed at /proposals/[slug]. Sign page deployed at /sign/[slug] with DocuSeal envelope embedded inline. Pre-flight check confirms both pages return 200 and the widget loads.
3
Send
Prince drafts the email in Pepe's voice, three to five sentences long with one link and no attachments. Pepe reviews and says Fire Away, which is the only phrase that authorizes the send. On delivery, CRM state moves to proposal and a Notion entry is created.
4
Monitoring
DocuSeal webhook fires on every signing event. Day 7 without signature: Lars posts a chase draft, Janis sends after Fire Away. Day 14: Pepe decides to extend, revise, or close. Day 28 still unsigned: lead moves to stale, engine closes, CAE owns re-engagement.
5
Close
Countersigned PDF pulled from DocuSeal, filed to client Drive folder as YYYY-MM-DD_[CLIENT]_Engagement-Letter_Signed.pdf. Lemmy contract registry updated. Countersigned EL event emitted to CAE Phase 5.4. Gene writes finance log entry.
Actor Map

Who does what

Eight roles across the engine, each with a specific handoff so no step is left with shared or unclear ownership.

Prince
Engine direction. Owns proposal narrative. Ensures the page reads as a deal-closing document, not a scope list.
Lemmy
EL structuring. Pulls canonical template. Confirms scope, fee, payment terms, jurisdiction. Runs conflict check.
Gene
Fee confirmation. Validates billing type, amount, schedule against approved rates. Flags non-standard terms.
Bruce
Framing review. Checks narrative against current MGL positioning before Pepe reviews for send.
Bowie
Infrastructure. Manages DocuSeal instance, webhook config, envelope status polling, route availability.
Lars
Delivery reliability. Monitors signing status daily. Flags unsigned proposals at Day 7 and Day 14 to alerts thread.
Janis
Execution. Builds the page, calls DocuSeal API, monitors webhook, emits countersign event to CAE, writes all logs.
Pepe
Showtime gate. Fire Away on every proposal email. Reviews EL terms on any non-standard scope.
Gates

What needs Pepe, what does not

Every proposal email requires an explicit Fire Away from Pepe before it leaves the drafts folder.

Gate Phase Type Trigger
Non-standard fee 1 Showtime Fee deviates from approved rate card
Conflict of interest 1 Showtime Any conflict detected in client registry
Proposal email send 3 Fire Away Every proposal, regardless of client, size, or urgency
Day 14 stale decision 4 Showtime Pepe decides: extend, revise, or close
Everything else 1 to 5 Soundcheck Janis executes, reports if noteworthy
Failure Modes

What breaks, how it gets caught

Every failure has a named detection point and a named responder.

Failure Detection Response
DocuSeal embed fails to load Phase 2 pre-flight check Bowie diagnoses. Proposal does not send until resolved.
Webhook not received after signing Lars Day 7 check Bowie confirms webhook config. Poll DocuSeal API directly for envelope status.
EL PDF generation error Phase 2 build Lemmy reviews template, regenerates. No send until PDF confirmed valid.
Client cannot access sign page Client reports Bowie checks routing. Fallback: generate direct DocuSeal signing link.
Infrastructure

What runs this engine

Self-hosted DocuSeal, static proposal pages, one webhook endpoint.

Signing Layer
DocuSeal, self-hosted on VPS. AGPL licence. Embedded widget renders inline on /sign/[slug].
Webhook Endpoint
POST /api/docuseal-webhook. Cloudflare Pages function, proxies to VPS handler.
EL Template
brain/areas/mexzungu/templates/engagement-letter-template.md. Lemmy owns. Never modified mid-engagement.
Signed PDF Naming
YYYY-MM-DD_[CLIENT]_Engagement-Letter_Signed.pdf, filed to Mexzungu Group Drive, client subfolder.
Proposal Pages
mexzungu.com/proposals/[slug]. Static. Deployed via deploy.sh.
Sign Pages
mexzungu.com/sign/[slug]. Same stack. DocuSeal embed only.
Cross-Engine Interfaces

How this engine connects to CAE

A single inbound trigger opens the engine, a single outbound event closes it.

CAE Phase 5.3 ➔ Proposal Engine Phase 1
Payload: contact, company, scope agreed, billing type, fee, discovery notes. Trigger: Go decision confirmed in CAE Discovery phase.
Proposal Engine Phase 5.3 ➔ CAE Phase 5.4
Payload: client ID, signed date, EL Drive link. Trigger: DocuSeal countersign webhook received and validated.
