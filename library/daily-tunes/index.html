Daily Tunes the system heartbeat

G3  ·  Owner: Lars (COO) + Bowie (CTO)  ·  Updated 2026-08-23
What It Is

The Pulse

Daily Tunes is the heartbeat of Janis infrastructure. It runs twice a day: 06:15 CET and 19:00 CET. Every run checks system health, synthesizes what happened since the last check, and surfaces what Pepe needs to know.

It is not a report. It is a pulse. A report is produced after someone asks. A pulse runs whether anyone asks or not. If Daily Tunes stops running, something is wrong. That is the point.

06:15 CET Run

Morning Check

What it checks

  • Overnight cron health — any failures, timeouts, or stalled processes since 19:00 run
  • Email triage — what came into all 4 inboxes overnight that is time-sensitive
  • Calendar — today's schedule, conflicts, missing prep, invites needing response
  • Client signals — any inbound from active clients requiring same-day response
  • Finance — new transactions, payment failures, or invoices that moved overnight
  • Social queue — what is scheduled to publish today, is the queue stocked
  • BD pipeline — any leads that need a follow-up today
  • Open flags from previous day — unresolved items from yesterday's evening check

Output: a structured brief posted to the Janis Telegram channel by 06:30 CET.

MORNING BRIEF [DATE] TODAY - [calendar item] [time] - [calendar item] [time] ACTION REQUIRED 1. [item requiring Pepe decision or action, with deadline] 2. [item] OVERNIGHT FLAGS - [cron failure or infra issue, if any] - [email requiring same-day response] PUBLISHING TODAY - [post title / platform] PIPELINE - [lead name, stage, next action due today] FINANCE - [any payment or invoice movement] CLEAN: [yes / no — if no, list what is not clean]

Pepe acts on ACTION REQUIRED items. Everything else is for awareness. If he sees nothing under ACTION REQUIRED and CLEAN is yes, his day starts free.

19:00 CET Run

Evening Check

What it checks

  • Cron jobs since morning — did everything scheduled during the day complete?
  • Email triage — what came in during business hours not already handled?
  • Tasks — what was supposed to be done today that is not done?
  • Client communications — any threads needing response before tomorrow?
  • Content — did scheduled posts publish correctly? Any failures?
  • Finance — any transactions or payments that cleared today?
  • Infrastructure — any service restarts, errors, or anomalies in logs
  • Prep for tomorrow — anything Pepe needs to know before his next morning

Output: a structured close-of-day post by 19:15 CET.

EVENING BRIEF [DATE] TODAY: CLOSED - [completed items] OPEN ITEMS - [not done today, carrying to tomorrow, with owner] TOMORROW - [calendar items] - [deadlines] INFRA - [any service anomaly or cron failure today] PUBLISHING TOMORROW - [scheduled content] EOD STATUS: [CLEAN / FLAGS]
Immediate Alerts

What Triggers an Alert Outside the Schedule

  • Tools server health check fails
  • A cron job not seen for more than 2x its scheduled interval (e.g., a 2-hour job not seen for 4+ hours)
  • Any email from an active client containing: urgent, deadline, ASAP, or similar time markers
  • A payment failure or returned payment notification
  • Any calendar conflict for an event within 24 hours
  • Social post that was scheduled but failed to publish

Immediate alerts are separate from the Daily Tunes briefs. They do not wait for 06:15 or 19:00.

When Daily Tunes Fails

Recovery Scenarios

ScenarioResponse
Brief does not post by expected timeJanis checks cron log. Bowie restarts, posts manual brief. Pepe gets one note: "Daily Tunes delayed, manual brief posted now."
Brief posts with errors (wrong date, missing section)Lars corrects and reposts. Alert to Pepe only if error was in an ACTION REQUIRED item.
Cron consistently failing across multiple runsBowie investigates. If not resolved within one run cycle, Pepe is notified: what failed, what was tried, what is needed.
Pepe stops responding to ACTION REQUIREDLars flags on day 3. One Telegram note: "Three ACTION REQUIRED items unacknowledged. Reply with item number to action or defer."
