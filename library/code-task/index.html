Code Task Procedure spawning autonomous build sessions

Core Infrastructure  ·  Owner: Bowie (CTO)  ·  Updated 2026-08-23
What It Is

Autonomous Build Sessions

A code task spawns a headless Claude Code session that builds, fixes, or deploys autonomously on the VPS. It returns a task ID immediately and sends Pepe a Telegram ping when done. No manual monitoring required.

Use for: building new features, fixing bugs in production code, refactoring scripts, updating configurations, writing tests. Not for work requiring Pepe decision-making mid-stream.

Spawn Command

How to Fire a Code Task

curl -s -X POST http://127.0.0.1:8741/code-task \ -H "Content-Type: application/json" \ -d '{"task": "...", "model": "sonnet", "commit": true}'

Parameters:

ParameterValuesNotes
taskAny stringFull task description. Be specific — the more context, the better the output.
modelsonnet / opusSonnet for code and automation. Opus for complex judgment and client deliverables.
committrue / falseWhether to git commit the output. Always true for production changes.
restart_serviceservice nameOptional. Service to restart on completion. See mandatory restart rule below.
ETA Rule

Always Include an ETA

Standing Order

Every code task kick-off must include a rough ETA. "On it" alone is not acceptable. Always: "On it. ETA ~X min. Ping coming." No exceptions.

5-10 min
Sonnet tasks
15-20 min
Opus tasks
20-30 min
Complex builds
Task Status Values

Lifecycle States

StatusMeaning
queuedTask received and waiting to start
runningSession active, build in progress
completeBuild done. If commit: true, changes are committed to git.
failedSession encountered an error. Relaunch immediately — do not wait for Pepe.
timeoutSession exceeded the time limit. Usually indicates a stuck process or task scope too large to handle in one session.
Mandatory Restart Rule

After Modifying Core Files

Any code task that modifies any of these four files must restart the janis-tools service as the final step — even if restart_service was not passed in the task params:

  • janis/tools_server.py
  • janis/kellen_dashboard.py
  • janis/dashboard.py
  • janis/dashboard_hub.py
systemctl --user restart janis-tools && sleep 5 && \ curl -s http://127.0.0.1:8741/health | head -c 100

Include the health check output in the Telegram notification. A committed change that is not live is not done.

Expected healthy response: {"status":"ok","tools":74}

Hard Limits

Discipline Rules

  • Tasks max 8 minutes before Bowie investigates
  • Relaunch on failure immediately — do not wait for Pepe
  • Never leave debug statements or print() calls in production output
  • "Committed" is not "live" — service restart confirms live status
  • Save lessons to brain before starting the next task
