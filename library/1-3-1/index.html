The 1:3:1 Framework

One problem. Three options. One recommendation. The MGL standard for surfacing any issue that needs a decision.

What It Is

The format for every escalation

1:3:1 is how MGL reports problems. Not raw logs. Not data dumps. Not Slack pings with a timestamp and a question mark. One problem stated plainly, three real options, one recommendation with a reason. That is everything needed to make a good decision fast.

If a problem is truly zero-action, say nothing. 1:3:1 is for things that require someone to act or decide.

The Structure
1
Problem
One sentence. Plain English. What broke, what is silent, what is wrong.
:
3
Options
Three real choices. Each different. Each with what it costs or risks.
:
1
Recommendation
Pick one. Say why. One sentence is enough.
The Template
[PROBLEM] One sentence. What broke, what is silent, what is wrong. Plain English. No jargon. No raw timestamps. [OPTIONS] 1. First option. What it involves. How long it takes. What it costs or risks. 2. Second option. Same structure. 3. Third option. Same structure. [RECOMMENDATION] Option X. One sentence on why.
Concrete Example
Before (raw dump)
STALE P1 JOBS: pipeline-tracker: silent 48.0h (threshold 36.0h)
After (1:3:1)
[PROBLEM] pipeline-tracker has been silent for 48 hours. It should run every 24 hours. [OPTIONS] 1. Restart the cron. Takes 5 min. Fine if failure was one-off. 2. Check logs for last error before restarting. Takes 15 min. Finds root cause. 3. Check if the data source itself is down first. Takes 5 min. Rules out cascade. [RECOMMENDATION] Option 2. A blind restart fixes nothing if the script errored. Read the log first.
Hard Rules

What makes a 1:3:1 valid

The PROBLEM line is one sentence. If you need two, you have not thought it through yet. Options must be meaningfully different. Do not use "do nothing" as a filler option. The RECOMMENDATION must pick one and say why, even briefly. No raw log data, no JSON, no cron timestamps in the output.
