1. The Hooks System (Almost Entirely Unused)

Claude Code supports 17+ hook events. Janis currently uses zero.

PreToolUseBefore any tool executes. Block send_email without "Fire Away" in context. Require ETA before code task. Prevent dashboard logging.
PostToolUseAfter any tool executes. Scan Write/Edit output for em dashes, Castilian markers, bold markdown in Telegram. Log all tool calls for audit.
PreCompactJust before context compaction. Flush standing orders (Showtime list, Fire Away rule) to disk so they survive compaction. Write rolling handoff.
SessionStartStdout is injected as guaranteed context. More reliable than CLAUDE.md injection. Model cannot deprioritize it.
StopWhen Janis finishes a response. Trigger inactivity handoff. Write session state.
NotificationBackground task completes. Route code task completions to Telegram correctly.

Critical implementation detail

Exit code 2 = block (prevents tool from running). Exit code 1 = log the error but run anyway. Every tutorial gets this backwards. Security hooks must use exit 2.

PreToolUse can transform, not just block

The updatedInput field lets the hook rewrite tool input before execution. Use cases: strip --force from git push commands automatically, add missing ETAs to code task descriptions, normalize file paths, redact sensitive data before it reaches external APIs.

HTTP hooks route to the tools server

PreToolUse can POST to http://127.0.0.1:8741/hooks/pre-tool-use. Every tool call Janis makes during Claude Code sessions can be logged, audited, and blocked by the existing tools server. The infrastructure is already there. It just needs to be wired up.

2. Context Architecture

The problem: everything loads on every session

CLAUDE.md @ imports pull in constitution, standing-rules (68 rules), all 7 Rock Council personas, tone-brain (27KB), profile, system-prompt, guides, and active tasks. Estimated per-session overhead: 40-60KB of context that is irrelevant to most tasks. A code task to fix a cron job loads the full Agathe ENM accountability framework.

Path-scoped rules

Files in .claude/rules/ use YAML frontmatter to load only when Claude reads a matching file path. Rock Council personas load only when working on a client file. Tone-brain loads only when working on content. Client overviews load only for their matching client path.

Restructuring recommendation

  • Keep always-loaded: constitution, Fire Away rule, Showtime list, top-10 most-violated rules
  • Move to path-scoped: Rock Council personas, tone-brain, client overviews
  • Result: 40-60% context reduction on code and infrastructure tasks

Sub-agent model routing

The CLAUDE_CODE_SUBAGENT_MODEL environment variable lets sub-agents run on Haiku while the parent session runs on Sonnet. 5-10x cost reduction for research, classification, and summarization sub-tasks with no quality loss on the complex reasoning that stays on Sonnet.

3. Memory Architecture

The Write-Manage-Read framework

Current Janis memory stack: Write (claude-mem observations, brain/ filesystem writes, Yoda rule updates) and Read (CLAUDE.md injection, MEMORY.md index, observation retrieval). The Manage phase is entirely missing.

Manage includes: deduplication, contradiction detection, expiration/TTL, compression, importance scoring, pruning. Without it, the corpus grows indefinitely and signal-to-noise degrades.

The reflection cron: highest-value missing piece

Production systems (Park et al., Reflexion, LangMem) run periodic synthesis passes: read recent episodic observations, identify patterns (recurring corrections, repeated mistakes), generate candidate rule additions, queue for review. Janis has 90K+ messages of episodic data and Yoda standing by. The connection between them is manual. A weekly reflection cron closing that loop automatically would continuously improve behavior.

Memory retrieval: from universal injection to task-specific

The Context Dump Fallacy: more context injected equals more noise equals worse reasoning. A 2025 enterprise AI analysis found context quality failures account for 65% of agent failures in production. Current Janis approach: inject everything at session start. Production pattern: assemble task-relevant context bundles based on what the session is about.

Structured world model

Current session handoffs are free-form markdown. Variable structure, variable depth. Production pattern: a structured YAML world model (300-500 words) injected at session start with explicit fields: current_focus, open_loops, decisions_this_week, rule_updates_pending, next_session_priority. Structured handoffs inject 10x more reliably than free-form markdown because the model can parse fields rather than extract meaning from prose.

4. Proactive Agent Gaps

Event-driven vs. scheduled: the architecture gap

Frontier systems run event-driven sentinel loops. Janis runs scheduled batch jobs. A deal going cold should trigger a reasoning loop within the hour, not be caught in the next 8am pipeline tracker sweep. An invoice arriving should immediately log to finance, not wait for the 4-hour cron.

Heartbeat pattern: a lightweight loop every 5-15 min checks current state against expected state and surfaces deviations immediately. Not a full reasoning session. Just a state check that decides whether to escalate.

5. Mistake Prevention

Why agents repeat mistakes: five root causes

Root cause 1: Compliance gap is structural. A May 2026 paper (arxiv:2605.01771) proved mathematically that the gap between what an LLM says it will do and what it does is inevitable under reinforcement learning. The model cannot catch its own process violations from text alone.

Root cause 2: U-shaped attention degradation. Rules in the middle third of a long system prompt receive 30%+ less attention. Janis's 68 standing rules are injected as a monolith. Most rules are buried in the middle.

Root cause 3: Training data defaults reactivate under load. Castilian Spanish is the model's default register. Markdown formatting is the model's default output style. These require active overrides that degrade when task-completion pressure rises. A hook scanning for them cannot be overridden.

Root cause 4: Context compaction erases behavioral calibration. Compaction preserves facts but loses emotional weight. The correction "do not use em dashes" survives compaction as a fact, but the context that made it salient does not. Post-compaction adherence drops measurably.

Root cause 5: Corrections are assumed, not verified. Writing a rule to standing-rules.md and calling it done repeats the same error as assuming the original instruction would be followed. There is no feedback loop from "rule written" to "rule verified."

The fix architecture: three layers

Layer 1: Structural enforcement (highest reliability)

Layer 2: Placement optimization. Move the 10 most-violated rules to the first 50 lines of CLAUDE.md and repeat them in the last block. The bulk of standing-rules.md stays where it is, but critical behavioral rules are no longer buried in the middle.

Layer 3: Domain-tagged injection. Instead of injecting all 68 rules always, inject 10-15 relevant rules at task time. Email task gets email rules plus Fire Away. Spanish content gets Mexican Spanish rules. Telegram send gets formatting rules. Reduces context noise and increases signal weight.

Rule testing: reliable@k

The Six Sigma Agent paper introduces reliable@k: how consistently a rule is followed across k similar scenarios. Any rule with k below 90% across 10 test cases is a tendency, not a rule. Yoda should build behavioral tests for the top 5 fuckup categories and run them after every rule update: em dashes, Fire Away, Castilian Spanish, false completions, commit-does-not-equal-live.

6. Claude API Optimization

Prompt caching: largest immediate cost win

The 74-tool block in tools_server.py is the largest stable block in every Janis request. It is almost certainly being sent uncached on every call across 35+ cron jobs and the messaging bot. Adding cache_control: ephemeral to the last tool definition caches the entire block at 10% of normal input cost on every subsequent read within the 5-minute TTL.

Estimated impact: 90%+ cost reduction on the tool definitions slice of every API call. At current cron frequency, this is the single largest cost win available.

Estimated savings: 40-60% reduction on cron job API spend by moving classification and extraction crons to Haiku.

Parallel tool calls

Many Janis cron jobs fetch email plus calendar plus tasks sequentially. With parallel tool call architecture enabled, these become simultaneous. Sequential (4 calls at 2s each): 8 seconds. Parallel (4 calls simultaneously): 2 seconds. For crons that run every 30 minutes, this compounds into significant latency reduction.

7. Implementation Roadmap

Sprint 1 Structural Enforcement (Week 1, highest ROI)

  1. PreToolUse hook: Fire Away gate. Block send_email unless "Fire Away" appears in recent context. Exit code 2.
  2. PostToolUse hook: content scanner. Scan every Write/Edit/Telegram-send output for em dashes, Castilian markers, bold markdown. Log violations to violations.log.
  3. PreCompact hook: rule flush. Write the top-10 standing rules and Showtime list to a temp file before every compaction. Inject on next session start via SessionStart hook.
  4. Fix hook exit codes. Audit any existing hooks. Ensure all blocking hooks use exit 2 not exit 1.

Sprint 2 Memory and Context (Week 2)

  1. Path-scoped rules restructure. Move Rock Council personas, tone-brain, client overviews to .claude/rules/ with path frontmatter. Estimated 40-60% context reduction.
  2. Reflection cron. Weekly Yoda run that reads recent claude-mem observations, generates candidate rule additions, queues for review.
  3. Structured world model. Replace free-form handoff markdown with a YAML schema. Session-start injection reads the world model file, not the raw handoff.
  4. Prompt caching. Add cache_control to tool definitions block in tools_server.py.

Sprint 3 Proactive Capabilities (Week 3)

  1. Absence detection. State file tracking expected events plus heartbeat check every 15 min. Surface absences via Telegram alerts thread.
  2. Commitment tracker. NLP scan of outbound messages for commitment language plus deadline extraction plus daily digest.
  3. Auto pre-meeting staging. 30 min before every external calendar event, auto-deliver structured brief to Telegram. No trigger required.
  4. Model routing. Switch classification and extraction crons to Haiku. Keep content and analysis on Sonnet.

Sprint 4 Testing and Learning Loop (Week 4)

  1. reliable@k tests. Yoda builds behavioral tests for top 5 fuckup categories. Runs after every rule update.
  2. Weekly self-diagnosis cron. Janis generates performance report: rules violated (from PostToolUse scan), tasks completed, memory staleness.
  3. Domain-tagged fuckup injection. Tag each fuckup entry with trigger domain. Inject only relevant subset per task type.
