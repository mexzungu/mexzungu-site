WhatsApp Group Access: WAHA Scope

Apr 2026 Tech 5 sources 10 min read

Key Findings

  • The Meta Cloud API (current setup) handles 1:1 messaging only. WhatsApp groups require a separate solution. WAHA runs in parallel without touching the existing Cloud API setup.
  • WAHA (WhatsApp HTTP API) is a self-hosted Docker container that wraps the WhatsApp Web JS client. It exposes a REST API on localhost:3000. No external service dependency. No per-message cost.
  • Baileys (the previous approach) was unstable, undocumented, and maintained by the community. WAHA provides the same underlying access with a stable REST wrapper, persistent sessions, a dashboard UI, and webhook support.
  • The WAHA container is already deployed on the VPS at port 3000 with a persistent session store. The blocker is not infrastructure. It is phone number: WAHA needs a number that is not already registered on the Cloud API.
  • Risk is moderate: WhatsApp can detect and ban accounts using unofficial APIs. Mitigation is using the WEBJS engine (already configured), throttling send rates, and treating the WAHA number as disposable if needed.

1. The Problem: Cloud API Cannot Read Groups

The current Janis WhatsApp setup uses the Meta WhatsApp Business Cloud API via a BSP (Business Solution Provider). This is the official, Meta-approved integration. It is reliable, compliant, and permanent.

Its hard limitation: it handles 1:1 messaging only. WhatsApp groups are not accessible via the Cloud API. There is no official Meta API for reading or sending group messages. This is not a configuration issue. It is an architectural constraint of the official API.

Pepe operates in WhatsApp groups that are relevant to his work: client groups, deal groups, NCA operational groups. Janis cannot see or participate in any of them. This is the gap WAHA fills.

2. What WAHA Is

WAHA (WhatsApp HTTP API) is an open-source, self-hosted Docker image that wraps the WhatsApp Web JS (WEBJS) client in a REST API. It mimics the behavior of WhatsApp Web running in a browser, but exposes that functionality via HTTP endpoints.

Capabilities WAHA adds that the Cloud API does not have:

  • Read and send messages in WhatsApp groups
  • Join groups via invite link
  • List all groups a number belongs to
  • Receive webhooks for group messages (same webhook structure as 1:1)
  • Read group participant lists
  • React to messages with emoji
  • Read message status (delivered, read)

WAHA is not affiliated with Meta. It uses the WhatsApp Web reverse-engineered protocol. This puts it in the same category as Baileys, WPPConnect, and similar tools. The difference from Baileys is operational maturity: WAHA provides a stable REST API, a dashboard UI, persistent session management, and active maintenance.

3. Architecture: Two Systems in Parallel

Cloud API (Meta)           WAHA (self-hosted)
  Port: none (webhook)       Port: 3000 (localhost)
  Number: business BSP       Number: second number (SIM or virtual)
  Scope: 1:1 only            Scope: groups + 1:1
  Webhook: /webhook          Webhook: /waha/webhook

The two systems run in parallel. Nothing about the Cloud API changes. WAHA sits alongside it on the same VPS, bound to localhost:3000. The tools server routes messages to the correct backend based on whether the target is a group or a 1:1 contact.

5. Cost and Risk

Cost

WAHA Community Edition (the version deployed) is free and open-source. The Docker image is maintained at devlikeapro/waha. No subscription, no per-message fee, no usage limits. WAHA Plus (paid tier) adds multi-device support and some enterprise features. Not needed for current scope.

Phone number cost: a virtual SIM or cheap eSIM costs approximately $5-15/month. A spare physical SIM on a prepaid plan can be as low as $3/month in Spain. One-time setup cost only if using a physical SIM.

Risk profile

WhatsApp detects automation via behavioral fingerprinting. Mitigation factors already in place:

  • WEBJS engine is configured (more human-like than raw protocol)
  • The WAHA number should be a "warm" number with existing WhatsApp history, not fresh
  • Send rate should be throttled (no bulk blasts)
  • The WAHA number is separate from the Cloud API number. A ban affects only WAHA, not the main business number.

Treat the WAHA number as semi-disposable. The Cloud API number is protected by Meta's compliance framework. WAHA can be rebuilt with a new number in under an hour if banned.

6. Implementation Steps

Infrastructure is done. The remaining steps are one-time setup:

  1. Choose a phone number. Best option: a virtual number (Twilio, Vonage) or a cheap eSIM not already registered on WhatsApp Business API. The number must have an existing WhatsApp account or be registered fresh via the WAHA QR flow.
  2. Start the WAHA session via the API or Swagger UI at localhost:3000.
  3. Scan the QR code. SSH tunnel to localhost:3001, open browser, scan from the phone with the new number. One-time only. Session persists in /home/mexzungu/waha-sessions/.
  4. Add Janis to groups. Either join via invite link through the WAHA API or add the WAHA number to groups from Pepe's phone.
  5. Test send/receive. Send a test message via the tools server. Verify webhook fires on incoming group message.

7. Decision

Proceed with WAHA

Infrastructure is deployed and tested. The only remaining blocker is obtaining a phone number for the WAHA session. This is a 30-minute task once Pepe confirms the number source.

Recommended number source: A virtual number via Twilio or a cheap Spanish prepaid SIM. Cost: under 10 EUR/month.

What this unlocks: Janis can read and participate in all WhatsApp groups Pepe adds the WAHA number to. Group messages route through /waha/webhook and are processed by the same Claude message handler as 1:1 messages.

What this does not change: The Cloud API setup remains untouched. All existing 1:1 messaging, webhooks, and business number compliance are unaffected.
