Entity Classification

What counts as a Task, a Project, a Cluster, an Orbit, or an Engine. The rubric Janis uses to decide what gets created and how.

Entity Types
Task
Atomic action
Single atomic action. Has a done state. Tracked in tickets.json via Lars. No sub-deliverables, no cluster needed.
Has a done state
Send signing link to Noah Chase SafetyWing claim Fix IRPF discrepancy
Project
Discrete deliverable
A specific output with a clear done state. Lives inside a cluster. Has a deadline. Has an owner.
Has a done state
NCA trademark filing Janis web app Miriam AI companion
Cluster
Ongoing context zone
A persistent area that is loaded and managed, not completed. Contains projects and functions. Never finishes.
No done state
duara nca janis
Orbit
Person in relational universe
A person in Pepe's relational universe. Classified by gravitational weight. Planet is daily or life-shaping. Moon is meaningful and recurring. Star is warm but distant.
No done state
Planet agathe-daumal
Moon daniel-tenner
Star yoeal-haile
Engine
Permanent business function
Permanent business function within a Macro Engine. Runs indefinitely. No done state. Four Macro Engines: Connection (Jagger), Value (Lars), Care (Sade), Core (Janis). Each has micro-engines beneath it.
No done state
client-acquisition-engine content-engine brain-infra

Decision Tree
New entity mentioned
 
Is it a named person?
   YES → ORBIT   brain/contacts/[name].md
 
Is it a single atomic action with no sub-deliverables?
   YES → TASK   tickets.json via Lars
 
Is it a permanent process within a Macro Engine?
   YES → ENGINE   brain/loops/[slug]/
 
Does it have a specific deliverable with a clear done state?
   YES → PROJECT   inside an existing cluster
 
Is it an external entity (client, partner, counterparty)?
   YES → CLIENT CLUSTER
 
Is it a personal life domain?
   YES → LIFE CLUSTER
 
Is it an internal business workstream?
   YES → INTERNAL CLUSTER

Infrastructure Checklists
Task
  • Row in memory/tickets.json via ticket_create
  • Assigned owner (Janis or Pepe or third party)
  • Deadline set or flagged as ASAP
Project
  • Row in memory/tasks_active.md with deadline
  • Drive subfolder: [Client Folder]/[YYYY-MM_project-name]/
  • Workstream row in parent cluster's Workstreams table
  • Log entry in parent's email-log.md or deal-log.md
Client Cluster
  • brain/clusters/[slug].md from clusters/_template.md
  • brain/clients/[slug]/overview.md with YAML frontmatter
  • brain/clients/[slug]/email-log.md (empty, header only)
  • Drive folder in the correct shared drive
  • Google Contacts: search first, create only if missing
  • Contract registered via Lemmy if EL exists
Orbit (person)
  • brain/contacts/[name].md
  • Google Contacts entry. search_contacts first, create only if missing
  • Backlink added to all relevant cluster files
  • Gravitational weight assigned: Planet, Moon, or Star
Engine
  • brain/loops/[slug]/STATE.md
  • Entry in REGISTRY.json: macro_engine + function + owner
  • Macro Engine assigned at kick-off (Connection / Value / Care / Core)
  • Cron or trigger defined before first run
  • Bowie design gate completed before any code written
What Does Not Get Created
  • Notion tasks. Tasks live in memory/tickets.json only.
  • Standalone project files outside a parent cluster. Projects live inside clusters.
  • Duplicate contact files. One canonical brain/contacts/[name].md per person.
  • A cluster for a named person. That is an orbit.
  • An orbit for an entity. That is a cluster.
  • An engine without Bowie design gate sign-off.
