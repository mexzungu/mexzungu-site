MGL Entity Lifecycle Framework

Projects · Tasks · Loops. How work enters, flows, and closes.
MGL Internal · 2026-08-22
Project

Discrete Deliverable

  • ◆Clear Done state (measurable, testable)
  • ◆Has a start and an end
  • ◆Owns a project file + cluster workstream row
  • ◆8-stage mandatory lifecycle
  • ◆Registered in tasks_active.md at DETECT
Task

Single Action Item

  • ◆Discrete action, completable in one session
  • ◆Lives in tickets.json (Lars canonical)
  • ◆No research or concept note required
  • ◆Simple Open to Done lifecycle
  • ◆Grows into project only via re-classification
Loop / Function

Ongoing Engine

  • ◆Runs on schedule or trigger, no end date
  • ◆Assigned to Macro Engine + named owner
  • ◆Has STATE.md + run.py + cron entry
  • ◆Monitored via connector-probe + cron-health
  • ◆Health states: Active / Degraded / Dead

Approval Gates

Budget Gate (Stage 5)

Under $100: free flow, no alert. $100-$250: alert Pepe for awareness (no approval needed). Above $250: explicit Pepe approval required before proceeding.

Explicit "See It First"

No approval needed between stages by default. Gate only appears if Pepe explicitly says "I want to see it first." Otherwise flow continues autonomously.

Fire Away (Stage 7)

Required when Deliver triggers a Showtime item: publish content, send invoice, sign contract, first contact with new person. Draft + wait for "Fire Away."

Entity Transitions When classification changes
Task to Project
A task that reveals multiple deliverables, a measurable Done state, or spans more than one session must be re-classified. Janis detects, registers in tasks_active.md, creates project file, starts Stage 1.
Project to Loop
After Stage 7 (Deliver), if the deliverable is an ongoing engine, it graduates to a Loop. Must have STATE.md + run.py + cron entry + Macro Engine assignment before considered live.
Loop to Retired
A Dead loop is rebuilt (new project at Stage 1) or explicitly retired with status="retired" in REGISTRY.json. Run.py and cron entry removed. Never silently abandoned.
Janis is the single detection point. Persona loops flag potential projects to Janis. Janis makes the classification call. If it qualifies as a project, Stage 1 runs immediately: tasks_active.md row + project file + cluster workstream row. No exceptions. No project exists only in conversation history.
